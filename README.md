# 语音驱动 Claude Code

对着麦克风说话，让 Claude Code 在你自己的电脑上干活，干完念给你听。

    🎤 常驻监听 → 📝 识别 → 🧭 前台分流 → 🧠 Claude 干活 → 🔊 念结果
                                  │
                          闲聊/常识 → 快模型自己答（~1 秒）
                          要动手     → 应声 + Claude Code（带工具）

---

## 它解决的核心矛盾

书上的语音助手延迟预算是 **0.9–2.3 秒**（VAD 500-800ms + ASR 50-200 + LLM 100-500 + TTS 200-500）。

但这里接的 LLM 不是"回答一句"的模型，是**带工具的 Coding Agent**。实测：

| 场景 | 耗时 |
|---|---|
| 最简回复 | 5.7s |
| 带工具读文件 | 10.6s |
| 真干活（开浏览器、跑命令） | 17–23s+ |

**超预算三倍起步。** 所以直接做级联流水线是没法用的——你说一句话，要干等十几秒。

解法是两层：

**① 快慢分离**（前台接话，后台干活）

直接让 Claude 干，等待期间耳边一片死寂，用户会以为它死了。
所以中间插一个**预生成好的应声**（"嗯，我看看"）——零延迟，只负责维持话头。

**② 分类路由**（不是每句话都值得惊动重武器）

大部分话根本不用查文件。所以前面加一个 flash 模型当**事件路由器**，
一次调用同时决定"自己答还是交出去"——闲聊/时间/常识 1 秒内自己答完，
只有真要动电脑才走 Claude Code。

结果：**最轻的问题从 10 秒压到 2.4 秒出声**（识别 0.7 + 分流 1.2 + 合成 0.5）。

## 架构

```
┌─ 后台线程 ────────────────────────────────────┐
│  持续读麦克风 → 能量 VAD 断句 → 队列            │
│  （播放时屏蔽收音，防自己听自己）                │
└───────────────────────────────────────────────┘
                    ↓
┌─ 主线程 ──────────────────────────────────────┐
│  取一句 → ASR → 前台分流 ─┬─ 直接答 → TTS      │
│                          └─ 要动手 → 应声      │
│                                     → Claude   │
│                                     → TTS      │
└───────────────────────────────────────────────┘
```

**它想事情的时候麦克风不关** —— 你在等待期间继续说，会排队，答完接着办。

| `租户配置/` | 客服人设与知识库（诊所 / 餐馆两个实例） |

## 跑起来

```bash
# 1. 装依赖
pip install sounddevice soundfile numpy requests

# 2. 配密钥（照 config.example.py 填）
cp config.example.py config.py

# 3. 跑
py 一直听着.py
```

**前置**：需要本机装了 Claude Code（脚本会自动去找 VS Code 扩展里的 `claude.exe`）。

## 工程上踩过的坑

写成代码注释了，这里挑几个关键的：

**headless 模式的权限**
无界面模式**弹不出授权窗**，不在白名单里的工具它会回一句"需要你授权"——
看起来像坏了，其实是没给权限。必须用 `--allowedTools` 显式列出来。
（也因此，白名单就是安全边界：语音识别会听错，**不要无脑全放行**。）

**`--continue` 首轮必失败**
该目录下没有历史对话时它报错，代码如果自动退回重试，等于**首轮白跑一遍**（十几秒）。
用状态位记住，只试一次。

**自动量噪反而更难用**
判定线 = 底噪峰值 × 倍数。但底噪一抖判定线就跟着涨，
反而把说话声挡在外面（实测底噪 0.0001、说话 0.014，自动算出来的线却卡在中间）。
改成固定值 + 命令行覆盖，并把**每秒电平落盘** —— 出问题不用看窗口也能诊断。

**回授**
喇叭和麦克风在同一个房间。播放时不屏蔽收音，助手会把自己的话录进去、
转成文字、当成用户输入再回一遍 —— 无限套娃。

**音量条写成了函数调用**
`音量条线程()` 而不是 `threading.Thread(target=音量条线程).start()`，
主线程永远卡在那个死循环里。现象是"音量条一直刷但永远不说第 1 轮"。

## 和它的对话长什么样

```
👤 你说： 帮我看看 python-study 目录里有多少个 py 文件
🧭 前台判定：要动手（1.2s）
⚡ 应声：好，我去查
🧠 Claude 干活中……（这段时间你继续说话，我会存着）
🤖 Claude（16.9s）：顶层目录里有一百九十九个 py 文件。
                    要是连子文件夹一起算，一共五百七十七个。
```

```
👤 你说： 今天星期几
🧭 前台判定：直接答（0.8s）
⚡ 快答：今天是 10 月 14 号，星期三。
   ⏱ 识别 0.7s ｜ 前台 1.2s ｜ 快答 3.1s
```

## 还没做

- **打断**：现在它想事情的时候你能继续说（会排队），但说"停"没法真的叫停它
- **流式感知**：ASR 边听边转 / LLM 预测执行 / TTS 增量合成，都还没上
- **回授抑制的代价**：它说话时你插话会丢
